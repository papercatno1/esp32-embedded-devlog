# 2026-11-02 开发日志

## 回合 #1 TF 卡复查：能写，但不能跟 LCD 一起挂着

**起因**：用户把 TF 卡格式化后插入，要确认卡行不行。

**过程**
1. 板子在线（`ver 0.3.4`、`up 14451`、`notes 3`、`ifs ffat`）。运行时 `M` → `OK M SDHC 29818 w=1`，说明**格式化后卡确实可写了**。
2. 顺手把「开机挂卡」加进固件（在 `ui_begin()` 之前探卡 + 3 次重试），并加了 FFat→SD 一次性迁移。
   结果开机后 `M` → `OK M ? 29818 w=0`：`cardType()` 返回 `CARD_NONE`，卡**掉线**了。
3. 试着把探卡挪到 LCD 初始化之后（并 `ui_bus_recover()`），仍然是 `w=0`。
4. 结论：`SCK 39 / MOSI 38` 被 LCD 与卡共用，**卡长期挂着就会被 LCD 的 SPI 重配弄掉**。
   运行时一次性挂载（挂 → 用 → 卸）才是稳的。

**改法（固件 0.3.5）**
- 开机不挂卡，彻底避免抢总线
- `M` 指令：`SD.end()` → 重新 `sd_probe()` → 测类型/容量/写测试 → `SD.end()` → `notes_refresh_img_fs()` 重新判定 → `ui_bus_recover()`
- 图片继续存内部 FFat（10 MB，3 张 320×212，重启不丢）

**验证**
- `OK M SDHC 29818 w=1`（临时挂载可读写）
- 硬复位后 `notes:3 / isz:17 / ifs:"ffat"`，`P 3` 显示图片 `bk=18478` → 图片仍在、正常绘制

**踩坑**
- `notes.cpp` 里 `notes_refresh_img_fs()` 用到了下面才定义的 `img_path()` → 需要前置声明，否则 `error: 'img_path' was not declared in this scope`
- `notes_refresh_img_fs()` 在 `notes_begin()` 之前调用时 FFat 还没挂载，迁移会静默不执行 → 必须放到 `notes_begin()` 里 FFat 挂好之后
- 开机写测试连续失败，但卸掉再挂就成功：说明不是卡的问题，是"常驻挂载 + 共用总线"的组合问题
